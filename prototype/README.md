# 肩义手 4-DOF MuJoCo 最小控制原型

这是用于先验证控制逻辑的**等效运动学模型**，不是从 `全体アセンブリ.f3z` 恢复出的真实机构模型。原始 CAD 文件未被修改。

## 已实现

- 固定肩部基座。
- 4 个逻辑主动自由度：肩屈伸、肩外展/内收、前臂前后、手开闭。
- J1/J2 两个控制模式；每个模式只控制图中对应的两个自由度。
- 松键后输入归零，位置目标不变，因此由位置伺服保持当前位置。
- 同时按 `W+A` 等可形成双轴输入；相反键（`W+S` 或 `A+D`）互相抵消。
- 窗口失焦、切换模式时清空按键状态，避免持续误动作。
- 50 Hz CSV 日志：时间、模式、输入、关节位置/目标和末端位置。
- 三个红色目标点仅用于显示，尚未加入依次到达/停留判定。

## 键位

| 模式 | W | S | A | D |
|---|---|---|---|---|
| J1 | 肩屈曲 | 肩伸展 | 肩外展 | 肩内收 |
| J2 | 前臂前 | 前臂后 | 手打开 | 手闭合 |

- `Space`：切换 J1/J2
- `R`：回到初始位置
- `Esc`：退出
- 鼠标滚轮：缩放

## 运行

建议使用 Python 3.10–3.12：

```bash
cd prototype
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python smoke_test.py
.venv/bin/python controller.py
```

程序退出时会在 `prototype/logs/` 中留下一个 CSV 文件。

本项目已使用 MuJoCo 3.8.1 做过 XML 编译与连续步进测试。要重复验证，运行 `smoke_test.py`；它会检查 4 路逻辑控制、左右手指同步约束、末端位置有限且仿真没有数值警告。

## 临时参数与不能得出的结论

所有暂定范围、初始角度和速度都集中在 `parameters.json`。当前值只为让模型安全、明显地运动：

| 逻辑自由度 | 暂定范围 | 暂定速度 |
|---|---:|---:|
| 肩屈伸 | −30°～100° | 35°/s |
| 肩外展/内收 | −10°～90° | 35°/s |
| 前臂前后 | −20°～110° | 45°/s |
| 手开闭 | 单侧 0～35 mm | 单侧 20 mm/s |

“前臂前/后”暂按一个肘/前臂俯仰转轴实现；若实机含旋转、四连杆或其他联动，必须替换。模型还省略了 CAD 外形、闭环连杆、传动、限位结构、碰撞、重力、质量/惯量、摩擦、力矩与真实电机控制。因此目前只能检查：

- 键位和模式切换是否符合预期；
- 运动正负方向是否正确；
- 粗略活动范围和目标任务流程是否合适。

不能用它评价结构干涉、承载、动力学、电机能力、能耗、人体舒适性或真实任务时间。

## 下一轮替换真实 CAD 的最小资料

1. Fusion 中每个刚性件分别导出的网格（优先 OBJ，统一米制）和整机 STEP 备查；
2. 4 个主动自由度的轴线上两点或“轴原点 + 单位方向”，以及零位；
3. 每个关节实机限位、额定运动速度；
4. 明确“前臂前/后”的机械动作；
5. 手部是否为单电机对称联动，以及开口量定义。

若有闭环连杆、被动联动或减速传动，还需要连杆连接关系与传动比；不能只依据零件名称或外观补全。

## Mjswan 接入边界

当前 XML 可由 `mujoco.MjSpec.from_file(...)` 读取，再交给 Mjswan `Builder`。但 Mjswan 的标准查看器不会自动获得这里 Python/GLFW 实现的 `W/S/A/D` 按下与松开逻辑，也不会自动写上述 CSV；若立刻只打包模型，会变成“能看、不能按本实验规则控制”。因此第一阶段以本地 MuJoCo 控制器作为可验收基线。待四个动作方向得到确认后，再把同一状态机移植到 Mjswan 前端并保留日志字段。
